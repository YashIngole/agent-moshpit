Agent Moshpit is a small desktop office for coding agents. Each agent you start is a real command-line program (Claude Code, Codex, Gemini CLI, Hermes, or one you add yourself) running in a terminal inside the window, and is drawn as a person at a desk. You see who is working, who has a hand up because they need you, and who is done.

This is the first published version. It is free, MIT licensed, keeps no account and no API key, and has no telemetry.

## Download

| System | File |
| --- | --- |
| Windows 11 (64-bit) | `agent-moshpit_windows_x64-setup.exe`, or the `.msi` |
| macOS, Apple Silicon | `agent-moshpit_darwin_aarch64.dmg` |
| macOS, Intel | `agent-moshpit_darwin_x64.dmg` |
| Linux (64-bit, WebKitGTK 4.1) | `.AppImage` for any distribution, `.deb` for Debian and Ubuntu, `.rpm` for Fedora and openSUSE |

You also need at least one agent program, installed and signed in the way its makers say. The office finds the ones you have and can install the ones published on npm.

## Opening it the first time

The installers are not signed with a bought certificate, so Windows and macOS stop you once.

- **Windows.** SmartScreen says "Windows protected your PC". Choose **More info**, then **Run anyway**.
- **macOS.** Open the `.dmg` and drag Agent Moshpit to Applications. The first time you open it, macOS says it cannot check the app and refuses. Open **System Settings → Privacy & Security**, scroll to the message about Agent Moshpit, and choose **Open Anyway**. If macOS says the app "is damaged" instead, run this once in Terminal and open it again:

  ```sh
  xattr -dr com.apple.quarantine "/Applications/Agent Moshpit.app"
  ```

- **Linux.** For the AppImage: `chmod +x agent-moshpit_linux_amd64.AppImage`, then run it. The `.deb` and `.rpm` install the usual way.

## What has and has not been tried

- **Windows 11 is the system the app is used and tested on, every day.** The release build was put through the real-app test before this release.
- **The macOS and Linux builds have not been used by hand by anyone yet.** They compile, and they pass the same automated checks as the Windows build on every change (types, unit tests, the interface driven in a browser, the Rust tests including real pseudo-terminals, and a full desktop build). That is all that is known about them. If you run one, please [say what breaks](https://github.com/YashIngole/agent-moshpit/issues).
- **Windows only, for now:**
  - A click on a notification opens that agent's terminal. On macOS and Linux the notification is shown, and a click does nothing more than the system does by itself.
  - The right-click **Paste** reads the clipboard without the webview asking first.
  - The webview's browser keys are turned off, so F5 does not reload the window.

## What is in it

**The floor.** One room per project, a desk per agent, and a status that is always a pose, a word and a colour: starting, working, needs you, done, idle, trouble, away. Amber means "needs you" and nothing else. A band across the top names whoever has waited longest, the window's title and the tray icon count them, the taskbar button flashes, and you get a notification unless you are already looking at that terminal.

**Real terminals.** Click a desk and their terminal opens beside the floor; hold Ctrl to open it beside the others, in a grid you can resize, rearrange by dragging, and zoom. Everything under a pane's header is the program's own screen. Close a pane and the program keeps running at its desk; close the window and the office stays in the tray.

**Knowing who needs you, without reading their screen.** Claude Code says so itself in its own session file. Every other program is read from how its terminal behaves: printing is working, a bell or a terminal notice wants you. Claude Code's and Codex's question about trusting a new folder is seen before the program starts, from their own settings.

**In a terminal.** Copy and paste as in any terminal, a picture on the clipboard pasted as the path of a file holding it, files dropped on a pane pasted as their paths, Ctrl and a click on a file path to open it in your editor at that line (Cursor, VS Code, Windsurf, Antigravity or Zed), a click on a web address to open it in your browser, find, text size, and 5,000 lines of scrollback.

**Desks.** A menu on every desk: rename, restart, stop, carry on, start another like this, open the folder in your editor, remove (with eight seconds to undo). A small dot marks a desk whose terminal has printed something since you last looked.

**After a restart.** Every desk comes back, away, showing its last screen as it was drawn. Carry on resumes the conversation where the program can (Claude Code, Codex, Hermes).

**Programs.** Thirteen are known by name, four of them (Claude Code, Codex, Gemini CLI, Hermes) by how they take a task and carry on. Installing and updating runs in a pane where you see every line. A few lines of JSON in `harnesses.json` add a program of your own.

**Keys.** Everything can be done from the keyboard; **⋯ → Keys** lists every shortcut.

The [README](https://github.com/YashIngole/agent-moshpit#readme) describes all of it, and lists the [known limits](https://github.com/YashIngole/agent-moshpit#known-limits).

## What it sends

Nothing, with one exception: unless `MOSHPIT_NO_UPDATE_CHECK` is set, it asks npm for the newest version of each agent program you have installed, when it starts and every 12 hours. The programs it runs talk to their own services as they always do.

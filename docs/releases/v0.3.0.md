Two additions to the first release: Antigravity CLI joins the programs the office knows well, and the office can now update itself.

If you have 0.2.0, download this version by hand once: 0.2.0 has no updater. From 0.3.0 on, new versions are offered in the ⋯ menu.

## New

**Antigravity CLI.** Google replaced Gemini CLI with Antigravity CLI (`agy`) for personal Google accounts in June. The office now starts it with a task, carries on its latest conversation in a folder, and updates it with `agy update`. Install it with Google's own script; the office finds it once it is there. Gemini CLI stays in the list for those it still serves (a paid API key, or an enterprise licence), so no desk goes missing. The Antigravity row was written from Google's documentation and has not been run by the makers yet; if it starts wrongly for you, please [say so](https://github.com/YashIngole/agent-moshpit/issues).

**Updates from inside the app.** When a newer version is out, a dot appears on ⋯ and the menu offers **Update to …**. Choosing it fetches the update, checks it against the app's own key, puts it in place and starts the office again. If agents are busy you are asked first and told who will carry on. Nothing is fetched until you choose it, and if it cannot be had the office says why and points to the download page.

To know that a newer version is out, the office asks its releases on GitHub when it starts and every 12 hours. `MOSHPIT_NO_UPDATE_CHECK` turns that off, together with the same question it already asked npm about your agent programs.

## Download

| System | File |
| --- | --- |
| Windows 11 (64-bit) | `agent-moshpit_windows_x64-setup.exe`, or the `.msi` |
| macOS, Apple Silicon | `agent-moshpit_darwin_aarch64.dmg` |
| macOS, Intel | `agent-moshpit_darwin_x64.dmg` |
| Linux (64-bit, WebKitGTK 4.1) | `.AppImage` for any distribution, `.deb` for Debian and Ubuntu, `.rpm` for Fedora and openSUSE |

The `.app.tar.gz` files and `latest.json` are what an installed office updates itself from; you do not need them.

## Opening it the first time

The installers are not signed with a bought certificate, so Windows and macOS stop you once.

- **Windows.** SmartScreen says "Windows protected your PC". Choose **More info**, then **Run anyway**.
- **macOS.** Open the `.dmg` and drag Agent Moshpit to Applications. The first time you open it, macOS refuses. Open **System Settings → Privacy & Security**, scroll to the message about Agent Moshpit, and choose **Open Anyway**. If macOS says the app "is damaged" instead, run this once in Terminal and open it again:

  ```sh
  xattr -dr com.apple.quarantine "/Applications/Agent Moshpit.app"
  ```

- **Linux.** For the AppImage: `chmod +x agent-moshpit_linux_amd64.AppImage`, then run it. The `.deb` and `.rpm` install the usual way.

An update fetched by the office itself is not a download from a browser, so it should not meet these warnings. That has not been tried yet.

## What has and has not been tried

- **Windows 11 is the system the app is used and tested on.** The release build was put through the real-app test before this release.
- **The macOS and Linux builds have not been used by hand.** They compile and pass the same automated checks as the Windows build.
- **The updater has been checked only as far as the offer.** A test starts the real app, lets it find a newer version at a pretend address, and sees it offered in the menu with nothing fetched. Fetching a real update and putting it in place has not been run by hand on any system. The first real update will be the test; if it fails, the office says so and the download page still works.
- **Windows only, for now:** a click on a notification opens that agent's terminal; the right-click Paste reads the clipboard without asking; the webview's own keys (reload, for one) are turned off.

Everything else is as in [0.2.0](https://github.com/YashIngole/agent-moshpit/releases/tag/v0.2.0). The [guide](https://github.com/YashIngole/agent-moshpit/blob/main/docs/guide.md) describes the app, and [limits.md](https://github.com/YashIngole/agent-moshpit/blob/main/docs/limits.md) lists what is known not to work yet.

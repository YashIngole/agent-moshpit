# Agent Moshpit v0.5.0

- Claude Code and Codex launched by Moshpit now receive an internal MCP connection. Ask an agent to start another session in its directory, delegate a task, and retrieve the result. Native CLI worktrees are supported too.
- Agents can name their own unnamed desk and describe their current activity. A name you supplied or edited stays protected, and observed approval prompts still take priority.
- Eleven office tools cover session discovery, new-session delegation, inbox tasks, explicit results and requests for your attention. Repeated requests reuse the same task rather than launching duplicates.
- Connections stay local, use a separate capability for each session, and expire when the program stops. Project scope and bounded delegation keep coordination within the current project. Prompts and results are saved locally in `coordination.json`.
- Existing-session tasks wait in an MCP inbox; the recipient checks it between stages of work. Completion requires an explicit result. Moshpit does not type into another terminal or answer its approval prompts.

This release also includes the optional local voice input and session-reliability changes prepared for v0.4.0. Voice input remains off until enabled; microphone and accent-quality validation remain manual, as described in the [voice validation record](https://github.com/YashIngole/agent-moshpit/blob/main/docs/reviews/voice-validation-2026-10-09.md).

The MCP integration is covered by core tests and a Windows desktop scenario using stand-in Claude/Codex agents with the real stdio bridge and native launch configuration. Live model delegation is not part of that automated verification. See the [internal MCP guide](https://github.com/YashIngole/agent-moshpit/blob/main/docs/internal-mcp.md) for tools and limits.

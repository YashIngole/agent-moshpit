# Agent Moshpit UX sweep, 8 October 2026

A walk through Agent Moshpit the way a vibe coder uses it every day, flow by flow, with what to change. No app code was changed for this review.

**How it was tested**

- **Demo mode** (`?demo=office|calm|empty|crowd`, Edge through Playwright) at 1280×800, 1440×900, 800×700 and 420×760, for layout and flow.
- **The real desktop app**: a copy of the debug build from 8 October, 23:59, run as its own instance with its own data folder. Agents were the repo's stand-in (`tools/e2e/fake-agent.mjs`) plus a small key probe that writes down every byte it receives. That probe is how this report knows exactly what each key, paste and drop delivers to a program.
- **Real Claude Code 2.1.290 and Codex** (the versions installed on this computer) were each started once with no task in a throwaway folder, to see their opening screens. Nothing was typed into them, and their trust questions were left unanswered.
- **Keys**: most were driven through the webview's debugging port. A short round of real Windows keystrokes, confined to the test window, checked the keys a browser might steal (Tab, Ctrl+R, F5, Ctrl+P, Ctrl+F, Ctrl+=, Shift+Enter, Alt+V). That round was cut short because the computer was in use.

Severity: **High** breaks a promise of the app or loses your place. **Medium** is friction you hit every day. **Low** is polish.
Effort: **XS** under an hour, **S** half a day, **M** one to three days, **L** a week or more.

## What works well and must be kept

- **The terminals are the real programs, drawn faithfully.** Claude Code's and Codex's opening screens render exactly as in Windows Terminal, and redraw correctly after a resize, a zoom and a floor round trip ([64](ux-sweep/64-real-after-roundtrip.png), [61](ux-sweep/61-real-claude-codex-opening.png)).
- **Keys reach the program.** Tab, Shift+Tab, Esc, Ctrl+R (history search), Ctrl+P, Ctrl+F, Ctrl+W, Ctrl+L, Ctrl+Z, arrows, Home, PageUp and F-keys all arrive. Shift+Enter arrives as ESC+CR, a new line in Claude Code. Alt+V, Claude Code's image paste on Windows, gets through. Ctrl+C copies only when text is selected and otherwise interrupts the program, which is exactly right.
- **The Ctrl+click grid.** Two, three, four, six, eight panes, laid out squarely. Terminals are never torn down when the grid changes. Edges drag, double-click evens them out, and the zoom button gives one pane the room and puts the others back exactly as they were ([13](ux-sweep/13-four-panes.png), [35](ux-sweep/35-crowd-nine-panes.png), [15](ux-sweep/15-zoomed.png)). Eight panes at 1440×900 were still readable.
- **Ctrl+\` both ways.** It isn't stolen by programs, and the floor and terminals swap instantly. Scrollback survives the round trip: the core keeps 512 KB per terminal, and the first line of the session was still there after coming back ([50](ux-sweep/50-real-scrollback-after-return.png)).
- **The New agent form.** A half-written task survives Esc. Recently used folders are one-click chips. Fields change per program (no task field for Hermes, the install line shown for a program not yet installed). Install-and-start runs in a visible pane and hands over to the agent in the same pane ([22](ux-sweep/22-new-agent-install.png), [27](ux-sweep/27-update-pane.png)).
- **The band**: one amber strip, one button, longest wait first, others queued as chips ([03](ux-sweep/03-office.png)). Its button opens the terminal beside your current panes rather than replacing one.
- **Programs die with the app and nothing is orphaned.** After Quit, every agent program was gone. On relaunch, desks came back away, and Ctrl+\` restored the previous layout with honest "Carry on" or "Start again" bars ([60](ux-sweep/60-real-reopened-terminals.png)).
- **Copy behaves**: drag to select, Ctrl+C copies, double-click selects a word. Web addresses get a pointer cursor and open in the browser, and only safe ones open.
- **The floor itself.** The art, the poses, the words-not-colours program tags, the status words, the room per project, the empty-office invitation ([01](ux-sweep/01-empty.png)). Keyboard on the floor is good: one tab stop, then arrow keys, then Enter.
- **Close the window and the office keeps working** from the tray, with agents still running. That is the right default. It only needs to be said out loud (see flow 18).

## Findings by flow

### 1. First launch with nobody in

**What happened.** A single "your office" room with a spare desk and a short paragraph explains the idea, with one button and its `n` shortcut ([01](ux-sweep/01-empty.png), real app: [40](ux-sweep/40-real-first-launch.png)). `n` opens New agent with the cursor in the task field ([02](ux-sweep/02-new-agent-empty-office.png)). In the real app the program list has 11 choices: four installed, my two hand-added rows, and five marked `get`. At 1280×800 this pushes **Start agent** below the bottom edge of the panel, so you have to scroll to find it ([41](ux-sweep/41-real-new-agent.png)).

**What a vibe coder expects.** One glance, one click, an agent running. The Start button always visible.

**Proposal.**
- Pin Start and Cancel to the bottom of the panel.
- Make Ctrl+Enter start from anywhere in the form.
- Collapse the `get` programs behind a "more programs…" row, so the four you have come first and the list is one line.
- The welcome text is good. Add one line telling people that Ctrl+click opens a second terminal beside the first, because nothing else teaches it (see flow 3).

**Severity.** Medium. Effort XS–S.

### 2. New agent: each program, with and without a task, with a separate copy

**What happened.**
- Claude Code, Codex and Gemini ask for a task; Hermes says it takes its task in its own terminal ([21](ux-sweep/21-new-agent-hermes.png)). A program not yet installed shows the exact npm line and the button becomes "Install X and start".
- Without a folder: "Choose the folder the agent should work in."
- With a task, the name is the start of the task cut at about 40 characters, sometimes mid-sentence: "Make the checkout total right when" ([42](ux-sweep/42-real-probe-started.png)). With no task and no name, the name is "Claude in web" or "Codex in web", and two agents in the same folder get the same name ([61](ux-sweep/61-real-claude-codex-opening.png)).
- "Work on a separate copy" explains itself well but doesn't say which branch you'll get. A new agent walks in to a desk and gets a pane of its own ([24](ux-sweep/24-new-agent-started.png)). After starting, the form is emptied and the copy checkbox resets.
- Ctrl+Enter in the task box does nothing.

**What a vibe coder expects.** Type the task, press Ctrl+Enter, watch it start. A short readable name. Two agents in one folder that can be told apart. The copy checkbox remembered when you are fanning out several agents on one repo.

**Proposal.**
- Ctrl+Enter submits (XS).
- Names: cut at a word boundary and drop trailing joining words ("when", "and", "the"). Number duplicates ("Claude in web 2"), or, better, let the user rename in place (top ten #6).
- Remember the copy checkbox per folder (XS).
- Later, a "start another like this" item on a desk's menu: same program, same folder, new task (S).

**Severity.** Low–Medium.

### 3. Opening a terminal by clicking a desk

**What happened.**
- A click opens the desk's terminal to the right of the floor, with keyboard focus in it. The desk is highlighted as open ([10](ux-sweep/10-one-terminal.png)).
- A second plain click on another desk shows that desk in the same pane.
- Clicking an **away** desk starts its program straight away: Claude resumes with `--resume`, others start afresh. There is no way to look at what an away agent last did without running it again.

**What a vibe coder expects.** Click shows it. Starting a program is a separate, deliberate act, especially when the reason for opening the desk was to remove it.

**Proposal.**
- Opening an away desk shows its pane with the "Their program is not running" bar and the **Carry on** / **Start again** button. It doesn't start the program.
- The pane already has that bar. Today it is only seen after Stop.
- Keep the last screen across restarts, at least its last screenful, so the pane isn't blank after a relaunch ([60](ux-sweep/60-real-reopened-terminals.png)).

**Severity.** Medium. Effort S (`office.show` in `src/lib/office.svelte.ts:216` calls `bridge.wake` first).

### 4. Ctrl+click to open beside, and the grid

**What happened.**
- The grid works and looks good: two side by side, three as two over one, four as two by two, six as three by two ([11](ux-sweep/11-ctrl-click-two.png), [12](ux-sweep/12-three-panes.png), [13](ux-sweep/13-four-panes.png), [34](ux-sweep/34-crowd-six-panes.png)).
- The only way to learn about Ctrl+click is a tooltip on the desk.
- There is no keyboard equivalent. Ctrl+Enter or Shift+Enter on a focused desk doesn't open beside.
- Opening a third pane throws away the sizes you dragged: a 610/250 split went back to 430/430. Closing the second of four panes moved the bottom-left pane to the top right ([14](ux-sweep/14-closed-one-of-four.png)). Panes jump around when you close one.
- You can't choose where the new pane goes (right or below), and you can't drag a pane to a new spot.

**What a vibe coder expects.** BridgeSpace and Warp make the grid the point. Windows Terminal and Warp let you choose the split direction and keep the sizes you set, and VS Code lets you drag terminals between groups. People also expect a visible "split" affordance, not only a modifier key.

**Proposal.**
- **Keep sizes.** A new pane splits the focused pane's share instead of `arrange()` evening everything out. A closed pane gives its share to its neighbour (`src/lib/layout.ts:64` and `:81`). S.
- **Open beside by keyboard and mouse.** Ctrl+Enter on a desk. A small split icon that appears on hover over a desk. Alt+Shift+D (Windows Terminal's "duplicate pane" key) opens the next desk beside.
- **Later:** drag a pane by its header onto another pane's edge to move it there (M).

**Severity.** Medium (sizes and jumping), High for discoverability for new users. Effort S + M.

### 5. Resizing panes and the floor

**What happened.**
- Pane edges and the floor edge drag smoothly. The terminal is told its size once the edge rests, so programs don't thrash.
- Double-clicking a pane edge evens the panes. Double-clicking the floor edge toggles between the strip and normal width. Arrow keys move a focused edge.
- The floor can go down to 200 px ([19](ux-sweep/19-strip-min.png)), but at that width the desks are unreadable (see flow 15).
- With real programs, a resize makes every visible program redraw, and the office counts each redraw as work (see flow 11).

**What a vibe coder expects.** Exactly this, plus the strip being a readable list.

**Proposal.** Keep it all. Fix the status side effect (top ten #7) and the strip (top ten #9).

**Severity.** Low.

### 6. Giving one pane the room

**What happened.** The zoom button fills the room with one pane and remembers the others ([15](ux-sweep/15-zoomed.png); real Claude Code: [62](ux-sweep/62-real-claude-zoomed.png)). The only sign that others are hidden is the pressed state of a small icon. There is no key for it.

**What a vibe coder expects.** Windows Terminal has "toggle pane zoom" and Warp has "maximize pane", both on a key. Also a hint like "3 more" so you don't forget the others are there.

**Proposal.**
- Ctrl+Shift+Enter toggles zoom.
- Double-clicking a pane header toggles it too, like double-clicking a window title bar.
- While zoomed, show a small "+3" chip in the header that lists and switches to the hidden panes.

**Severity.** Low–Medium. Effort XS–S.

### 7. Putting a pane away

**What happened.** The × on a pane hides it, and its tooltip says the program keeps running. Desks whose panes are hidden show as not open on the floor. This is clear enough once learned.

**What a vibe coder expects.** In every terminal app, × on a tab or pane ends what is in it. Here it doesn't, which is the safer choice for agents, but it is the opposite of what people expect. That is why the owner looked for a "close" on the strip (see flow 10).

**Proposal.**
- Keep × as "put away".
- Show a one-time hint: "Put away. Claude Code keeps running at its desk. To end it: right-click the desk → Remove."
- Bind Ctrl+Shift+W to put away the focused pane (Windows Terminal's close-pane key). The program keeps running either way.

**Severity.** Low. Effort XS.

### 8. Going back to the floor and returning (Ctrl+\`)

**What happened.**
- Ctrl+\` and "back to the floor" put the panes away, and Ctrl+\` or "terminals" brings back exactly the same set. That's good.
- But if, while on the floor, you click (or Ctrl+click) **any** desk, the remembered set is thrown away. You get a single pane, and Ctrl+\` after that only knows that one.
- Steps: three panes open → Ctrl+\` → click another desk → you have one pane, and the other two have to be found and Ctrl+clicked again.
- In code, `#place` (`src/lib/office.svelte.ts:232`) uses the stowed layout only when the desk clicked was already in it.

**What a vibe coder expects.** The floor is a place to glance and pick. Picking someone should bring the grid back with that person in it, the way switching tabs in any terminal leaves the other tabs alone.

**Proposal.** When the room is empty and a stowed layout exists, start from it:
- A plain click swaps the clicked desk into the last focused pane.
- Ctrl+click adds it beside.
- The band's button adds beside, as it already does.

**Severity.** High for the owner's flow. Effort S.

### 9. Stopping and starting a program

**What happened.**
- Pane ⋯ → **Stop their program** ends it. The desk turns away, and the pane keeps the last screen with "Their program is not running" and a **Carry on** button (Claude, resumable) or **Start again** button ([43](ux-sweep/43-real-stopped.png), [65](ux-sweep/65-real-stopped-real-clis.png)).
- The menu text is honest: "The conversation is kept" for Claude, "they start afresh next time" for Codex when its session wasn't captured.
- "Start again" wipes the screen and starts the program fresh ([44](ux-sweep/44-real-restarted.png)).
- No **Restart** (stop and start in one go) exists, which is the usual fix when a CLI gets wedged.

**What a vibe coder expects.** Stop, Restart, and the conversation kept wherever possible.

**Proposal.** Add **Restart** to the pane and desk menus (XS). Put Stop in the desk's right-click menu too (see flow 10).

**Severity.** Low.

### 10. Removing a desk, and closing a desk from the strip

**What happened.**
- The only way to remove a desk is: open its terminal (which **starts its program** if it is away), then ⋯ on the pane, then **Remove this desk**, then the red **Remove the desk** button ([16](ux-sweep/16-pane-menu.png), [17](ux-sweep/17-remove-confirm.png), [66](ux-sweep/66-real-remove-confirm.png)).
- Desks themselves have no close button, no middle-click and no context menu.
- Right-click on a desk shows Edge's own menu, with Back, Refresh, Save as, Print, More tools and Inspect ([48](ux-sweep/48-real-right-click-desk.png)).
- Esc doesn't close the pane's ⋯ menu.

The owner tried to close a desk from the left strip expecting it to behave like closing a tab. Nothing on the strip supports that.

**What a vibe coder expects.** Windows Terminal and VS Code: hover a tab → ×, middle-click closes, right-click gives Rename, Duplicate, Close and friends. BridgeSpace and Warp work the same way with tabs and panes.

**Proposal.** One context menu, reachable from a desk on the floor, a desk in the strip and a pane header:

- Open · Open beside · Rename · Restart · Stop · Remove…
- Copy folder path · Open folder in Explorer · Open in VS Code

Plus:
- A small × on hover in the strip, and middle-click: **Remove**, with an Undo toast for about 8 seconds instead of a confirm box. Keep the confirm only when the agent is working or needs you.
- Removing never wakes an away program.
- Esc closes the pane menu.

**Severity.** High (the owner's explicit complaint). Effort S–M.

### 11. Someone needing you: band, raised hand, status

**What happened.**

**The hand drops by itself (bug).** The stand-in program rang the bell. Its desk raised a hand with "needs you", and the pane header turned amber ([53](ux-sweep/53-real-needs-you-pane-open.png)). Then I went back to the floor, whether by the button, by Ctrl+\` or by the pane's ×. In every case the band showed for a moment, and within about a second the desk turned **done** ("Finished. Open their terminal to see what they did.") and the band disappeared ([54](ux-sweep/54-real-hand-dropped.png)). Nothing had been answered.

**Cause** (from an IPC trace):
- When a pane loses focus or closes, xterm sends the focus-out report `ESC [ O`. ConPTY turns focus reporting on.
- It goes through `term_write` like a keystroke. `Terms::write` (`src-tauri/src/pty.rs:221`) calls `Pulse::input` (`src-tauri/src/status.rs:93`), which clears the bell notice.
- The next look sees "quiet after work", which reads as done.
- Clicking from one pane to another sends the same report, so by the same path it should drop the hand too. I didn't check that case separately.
- This affects every program whose status comes from terminal activity: Codex, Gemini, Hermes, OpenCode and every row a user adds. Claude Code's status comes from its session file instead.

**Status from activity is noisy.**
- Opening a second pane, dragging an edge or zooming makes every visible program redraw. Redraws count as work: the top bar flashed "2 working" for two programs sitting idle at a prompt ([64](ux-sweep/64-real-after-roundtrip.png)).
- When the window wasn't in front, the same thing ended with both desks marked **done** ([61](ux-sweep/61-real-claude-codex-opening.png)), which would also send "X is done" notifications.

**First-run questions aren't "needs you".** Claude Code ("Is this a project you created or one you trust?") and Codex ("Trust this folder?") both open with a question in a new folder. Both desks showed done or idle, with the "Finished" check-mark pose, never the raised hand.

**Notifications and the taskbar.**
- Notifications are sent for needs you, done and trouble, but clicking one doesn't open that agent: the notification plugin has no click action here.
- The taskbar button doesn't flash, and the window title stays "Agent Moshpit". Only the tray icon changes.

**What a vibe coder expects.** A raised hand stays up until they actually answer. "Done" means the agent did something. A first-run question is a question. Windows Terminal flashes the taskbar on a bell, and Warp notifies when an agent needs you.

**Proposal.**
- **Treat terminal reports as non-input (XS).** In `Terms::write`, don't call `pulse.input` when the data is only terminal reports: focus in/out (`ESC [ I`, `ESC [ O`), cursor-position and device-attribute replies, OSC colour replies. Alternatively, give reports their own command that never touches the pulse.
- **Ignore redraw after resize (S).** Ignore output for about a second after a resize, the way `ECHO_MS` ignores the echo of a key.
- **Don't count the opening screen as "finished" (S).** A program that drew its opening screen and went quiet before anyone typed hasn't finished anything. If it went quiet with its cursor on a prompt it drew itself, call it needs you, or at least "waiting for you" in the idle pose.
- **Taskbar (XS).** `request_user_attention` on needs you while the window is unfocused, a count in the window title ("(2) Agent Moshpit"), and an overlay badge.
- **Notifications (S–M).** Make a notification click open the window on that agent's terminal.

**Severity.** High (the hand), Medium–High (the rest). Effort XS to M.

### 12. The Agent programs panel, installing and updating

**What happened.**
- The ⋯ menu shows a dot and "2 updates out: Claude Code, Gemini CLI" ([25](ux-sweep/25-app-menu.png)).
- The panel lists every program with its version, the exact command, and install or update buttons. Updating runs in a pane and ends "Claude Code updated" ([26](ux-sweep/26-programs.png), [27](ux-sweep/27-update-pane.png)).
- **The panel is wider than itself at every window size.** The update buttons and the "→ 2.1.294" version text are cut off on the right: the buttons end 25 px past the edge at 1280, 1440 and 1920 px wide.
- The likely cause is the long `MOSHPIT_NO_UPDATE_CHECK=1` word in the footer, which forces the `.body` grid column wider (`src/components/Programs.svelte:148`, `:217`).

**What a vibe coder expects.** One click to update, with the button visible.

**Proposal.** Give `.body` `grid-template-columns: minmax(0, 1fr)` and let the footer's `code` wrap (XS). Also consider an "Update all" button when two or more updates are out (XS).

**Severity.** Medium (visible on every open). Effort XS.

### 13. A narrow window

**What happened.**
- Below 760 px a terminal takes the whole window and the floor waits behind, with "back to the floor" in the bar ([29](ux-sweep/29-narrow-terminal.png)).
- At 420 px with a terminal open, the ⋯ menu is pushed past the right edge, so Agent programs and Quit can't be reached. In demo mode the "demo data" chip takes some of that space. By the widths involved, the same happens without it at the app's 340 px minimum.
- The amber band takes 186 of 760 px ([28](ux-sweep/28-narrow-floor.png)).
- Ctrl+click in a narrow window opens one pane only ([30](ux-sweep/30-narrow-two.png)). That is reasonable, but nothing says so.

**What a vibe coder expects.** A narrow window kept at the side of the screen while coding: the bar, the band and a terminal, all usable.

**Proposal.**
- Shrink "back to the floor" and "+ new agent" to icons below about 520 px, so ⋯ always fits (XS).
- Make the band one line when narrow: face, name, button (XS).

**Severity.** Medium. Effort XS.

### 14. A crowd of 20

**What happened.**
- The floor needs more than two screens of scrolling at 1440×900, and only 8 of 20 desks are on screen ([04](ux-sweep/04-crowd-20.png)).
- Each room takes a full row even when it has four desks, leaving empty space on the right.
- The top bar says "2 in trouble", but those desks are off screen, and the counts can't be clicked.
- With terminals open, the floor column shows about five of the 20 desks beside four panes, none of them the two who need you ([32](ux-sweep/32-crowd-four-panes.png)), and the strip shows 8 of 20 ([33](ux-sweep/33-crowd-strip.png)).

**What a vibe coder expects.** At 10 to 20 agents, a dense list or small tiles, with whoever needs you, is in trouble or is done on top.

**Proposal.**
- Make the top-bar counts buttons that scroll to and highlight the first such desk, cycling on repeat clicks (XS).
- Add a density switch (comfortable or compact), turned on automatically above about 8 agents (M). Compact means a half-height desk: portrait head instead of the full scene, name, status, tag.
- Sort or filter by "needs attention" (S).

**Severity.** Medium. Effort XS–M.

### 15. The strip beside the terminals

**What happened.**
- At the default 420 px the floor beside the terminals is fine ([10](ux-sweep/10-one-terminal.png)).
- At the strip width (264 px) or the 200 px minimum, names are cut to "Refact…", "Bellrin…", "Claud…", and the status reads "away 1" ([19](ux-sweep/19-strip-min.png), [63](ux-sweep/63-real-strip-with-claude-codex.png)).
- Each room still draws its sign and a full-size "add an agent" box.
- This strip is the tab bar of the app, and today it behaves like a shrunken floor.

**What a vibe coder expects.** A vertical tab list like VS Code's terminal list or BridgeSpace's sidebar: full names (wrapping to two lines is fine), a status dot, the program tag, × on hover, drag to reorder, and needs-you pinned to the top.

**Proposal.** Below about 300 px, draw each desk as a list row: small portrait, name on up to two lines, status dot, × on hover. Replace each room's spare desk with a "+" in the room sign, and keep needs-you rows at the top of their room (M).

**Severity.** Medium. Effort M.

### 16. Keyboard-only use

**What happened.**
- **On the floor, good.** Tab goes New agent, then ⋯, then the band button, then the floor as one stop. Arrow keys walk the desks, Enter opens one, `n` opens New agent, Esc closes panels.
- **Between panes.** Ctrl+Shift+] and Ctrl+Shift+[ move between panes. That is undocumented, and the bar shows only Ctrl+\` and `n`.
- **Missing pane keys.** None for close or put away, zoom, jumping to pane N or desk N, opening beside (Ctrl+Enter on a desk does nothing), New agent from inside a terminal (`n` is typed into the program, which is right, but there is no Ctrl-chord either), font size (Ctrl+= and Ctrl+- do nothing at all), or quitting.
- **Inside a terminal**, Tab goes to the program as it should. So the only way out to the pane buttons by keyboard is Ctrl+\` to the floor.

**What a vibe coder expects.** The Windows Terminal and VS Code set, since that is where their muscle memory comes from.

**Proposal.** Bind these, catching them before xterm, like Ctrl+\`:

| Key | Does |
|---|---|

### 17. Copy, paste, links and scrolling in a terminal

**What happened.**
- Copy: select, then Ctrl+C. Double-click selects a word.
- Paste: Ctrl+V and Ctrl+Shift+V paste text.
- Scrolling: the mouse wheel scrolls the 5,000-line scrollback.
- Links: `https://` addresses and `http://localhost` show a pointer cursor and open in the browser ([57](ux-sweep/57-real-link-hover.png)). `http://example.org` is refused silently. File paths and `file.ts:120` aren't clickable ([56](ux-sweep/56-real-links-printed.png)).
- Missing:
  - no find in the scrollback (Ctrl+Shift+F in Windows Terminal, Ctrl+F in VS Code);
  - no right-click copy or paste (see flow 19);
  - no copy-on-select option;
  - coming back from the floor puts you at the bottom, not where you were scrolled.

**What a vibe coder expects.** Ctrl+click on `src/app.ts:42` opens it in the editor at that line, as in VS Code's terminal. Finding the error message from ten minutes ago. Right-click to paste, as in Windows Terminal.

**Proposal.**
- Add a link provider for paths (relative to the agent's folder) with `:line`, opening in the user's editor. VS Code's `code -g path:line` is a fine default (M).
- Add the xterm search add-on on Ctrl+Shift+F (S).
- Add a right-click menu with Copy, Paste and Select all (top ten #5).
- Say why a refused link was refused, in a small note (XS).

**Severity.** Medium. Effort S–M.

### 18. Images and files: pasting a screenshot, dropping a file

**What happened.**
- **Ctrl+V with an image on the clipboard** (a 64×48 bitmap put there for the test): the program received nothing.
- **Alt+V** reached it as ESC+v. That is Claude Code's image-paste key on Windows, so Claude can still paste images if you know Alt+V.
- **Codex** pastes images on Ctrl+V. With the app turning Ctrl+V into a text paste, Codex never sees the key. I didn't check this inside Codex, because doing so meant interacting with it.
- **Dropping a file onto a pane** does nothing. The page has no drop handler. On Windows, Tauri's own drag-and-drop handler sits in front of the page, and nothing listens to its event.

In Windows Terminal, dropping a file pastes its path, and that is the usual workaround when Alt+V fails in Claude Code (see the issues linked under Sources).

**What a vibe coder expects.** Win+Shift+S, then Ctrl+V into the agent, works. Dragging a screenshot or a file from Explorer onto an agent's pane works.

**Proposal.**
- **Drop.** Listen to the webview's drag-drop event. Use its position to find the pane under the pointer, focus it, and paste the quoted paths as one bracketed paste, exactly like Windows Terminal. Highlight the pane while something is dragged over it (S).
- **Paste.** When a paste event carries no text but the clipboard has an image, send the program the raw Ctrl+V (`\x16`) so it can read the clipboard itself. Or save the image to a temp `.png` and paste its path, which works for every program (S).

**Severity.** High for a vibe coder. Effort S.

### 19. The window acting like a browser

**What happened.**
- **F5 (real keystroke)**: it reached the program as `ESC[15~`, and then the whole window reloaded. The panes were gone, I was on the floor, and Ctrl+\` brought the set back.
- **Ctrl+R** went to the program, as it should for Claude Code's history search, and didn't reload.
- **Right-click** anywhere shows Edge's menu: Back, Refresh, Save as, Print, More tools, Inspect ([48](ux-sweep/48-real-right-click-desk.png)).
- **DevTools**: in this debug build, Ctrl+Shift+I or F12 opened a DevTools window. Release builds normally leave DevTools out, so that part may be debug only. The browser menu and F5 are not.

**What a vibe coder expects.** It's an app. Right-click in a terminal gives copy and paste. Nothing reloads.

**Proposal.**
- Turn off the webview's browser accelerator keys and default context menu, through the WebView2 settings via Tauri. Alternatively, call `preventDefault` on F5 and on `contextmenu` at the window level.
- Then show the app's own menus:
  - on a desk or pane header: the desk menu from flow 10;
  - in a terminal: Copy, Paste, Select all, Clear, Find…

Effort S.

**Severity.** Medium–High.

### 20. Renaming an agent

**What happened.**
- The core has a `rename` command (`src-tauri/src/office.rs:225`). A user's name is locked against later automatic names, and Claude's own session names flow in through `suggest_title`.
- The window's bridge exposes `bridge.rename`, but no part of the window calls it. Double-clicking a desk name or a pane title does nothing, and there is no menu item.
- The only chance to name an agent is the optional Name field at creation.

**What a vibe coder expects.** Double-click the title (VS Code terminal tabs, Windows Terminal tabs) or press F2, type, Enter. Names change as the task changes ("auth fix" becomes "auth fix + tests").

**Proposal.**
- Make the pane header's title (and the desk name in the strip) editable on double-click or F2.
- Add Rename to the desk menu.
- Enter saves, Esc cancels, and an empty name goes back to automatic.

Effort S.

**Severity.** Medium.

### 21. Closing the office: the window's ×, Quit, and reopening

**What happened.**
- **The window's ×** hides the window. The app and every agent keep running in the tray, and nothing tells you so.
- **Launching the app again** brings the window back, on the floor, with a "terminals" button. The panes that were open are not reopened ([58](ux-sweep/58-real-reopened-after-x.png)).
- **Quit** is the third item in ⋯ and in the tray menu. With agents working it asks first, in a native dialog with "Quit and stop them" and "Keep running". The dialog says: "2 agents are still busy. Quitting ends their programs. Their conversations are kept, and they carry on when you open their desks again."
  - That is true for Claude Code. It isn't true for programs the office can't resume: Gemini and the hand-added ones start afresh.
  - The ⋯ menu's line "Ends the agents' programs; their conversations are kept" has the same problem.
- **After Quit**, everything ended. On relaunch, desks were away and Ctrl+\` restored the last layout ([59](ux-sweep/59-real-reopened-after-quit.png), [60](ux-sweep/60-real-reopened-terminals.png)). Their old screens were blank, because the 512 KB kept per terminal lives only in memory.

The owner wondered how to close the whole office.

**What a vibe coder expects.** Windows Terminal asks before closing a window with several tabs. Apps that live in the tray (Discord, Docker Desktop) say so the first time you close them.

**Proposal.**
- **First close.** Show a notification: "Agent Moshpit is still running in the tray, with 3 agents. Quit from the tray or ⋯ → Quit (Ctrl+Q)." Add a setting "Closing the window quits", off by default (S).
- **Ctrl+Q** quits (XS).
- **Honest dialog.** Name who can't carry on: "Gemini CLI agents start afresh" (XS).
- **Reopening the window** restores the panes that were open (XS: start from the stowed layout).
- **Later:** write each terminal's last screenful to disk on quit, so an away desk shows what it last said (S–M).

**Severity.** Medium.

### 22. Hand-written programs (`harnesses.json`)

**What happened.** My first `harnesses.json` had invalid JSON (unescaped backslashes). The app ignored the whole file without a word, and my programs simply weren't offered (`src-tauri/src/harness.rs:186`).

**What a vibe coder expects.** "harnesses.json line 2: bad escape. Your programs were not loaded."

**Proposal.** Put the parse error in the problem strip on start, or in the Agent programs panel. Add an "Open harnesses.json" button there, since the file lives in the app data folder (XS–S).

**Severity.** Low.
